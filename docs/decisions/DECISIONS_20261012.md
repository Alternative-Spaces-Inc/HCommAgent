# HCA design decisions (2026-10-12)

9. P21b owner selections (08:0x PT, one widget per decision, after HCommAgent PR 3 merged as main c79821a8 and the plan v1 PR 4 opened): (1) api keys carry a fixed scope vocabulary of four scopes, `asks:create`, `asks:read`, `asks:cancel`, `webhooks:manage`, stored as a JSON list on the key row; issuance without a list grants all four, the migration backfills all four on existing rows, and a call without the needed scope is refused with 403 naming the scope. Declined: no scopes in v1 (rate limits and rotation only), free form scope strings matched by prefix. Plan: docs/plans/HCA_P21B_API_KEY_HARDENING_v1.md section 6. (2) rate limits are two integers on the key row, `rate_per_minute` default 600 and `asks_per_minute` default 60, admin adjustable, plus an optional per tenant `asks_per_day`; enforced by one upsert on a `rate_counters` table in the database so every Cloud Run instance shares one count; over the limit answers 429 with `Retry-After`, and every agent response carries `X-RateLimit-Limit` and `X-RateLimit-Remaining`; a fixed window may admit up to twice the limit across a boundary, accepted for v1. Declined: per instance in memory counters, no limits in v1.
