# 2026-10-02: HCA-P9, golden-path smoke test in the pipeline

## Why

Plan Day 10 asks for a smoke script that completes under 300 seconds. The
unit tests run through a TestClient; the PR 20 defect (inbox items without
`request_id`, popup answering against `undefined`) lived in the wire
contract between the extension and the server and only showed up live.
A script that speaks real HTTP the way the extension does catches that
class before the image is built, and a second pass after deploy proves the
new revision serves agent traffic against Cloud SQL.

## What this change does

- `scripts/smoke_golden_path.py`: one file, stdlib plus `cryptography`.
  `--human` runs the full path (admin mints a key, registers a P-256 test
  device, posts an ask with a webhook, reads the inbox signed and asserts
  the item carries `request_id`, answers signed, asserts a second answer is
  409, waits for the webhook, reads the audit row signed, asserts a bad
  signature is refused, revokes the device). Without `--human` it runs the
  agent path only: healthz, key, ask, read, cancel, read cancelled. Every
  check prints PASS or FAIL with elapsed time; first failure exits 1; the
  run fails itself past 300 seconds.
- `cloudbuild.yaml`: step `smoke-local` after `pytest` (local uvicorn,
  SQLite, gate off, `--human`), step `smoke-live` after `deploy` (agent
  path against the new revision, admin token from Secret Manager through
  `availableSecrets`, exposed only to that step).
- Runbook step 11b: the one IAM grant (`secretAccessor` on
  `hca-admin-token` for the build service account).

Local run of both modes against uvicorn before the PR: 13 of 13 and 7 of 7
PASS, each under 2 seconds.

## Red gate (owner)

`roles/secretmanager.secretAccessor` on the single secret `hca-admin-token`
for the compute service account the trigger runs as. Without it the
`smoke-live` step fails and the merge build goes red after the revision is
already serving (deploy is step 5, smoke is step 6), so grant first, merge
second.

## Proof plan

Merge this PR after the grant. Expect the triggered build to show eight
steps SUCCESS including `smoke-local` and `smoke-live`, and the
`smoke-live` log to end with `OK agent path, request <id>`.

## First two merge builds

- Build `87d896e1` (main `8aca3322`): rejected before step 0. Cloud Build
  read `$URL` and `$(...)` inside the smoke step scripts as its own
  substitutions. Fix: `$$` escapes (PR 29). No revision was deployed.
- Build `fef284a7` (main `80a0f422`): seven steps SUCCESS including
  `smoke-local` (13 of 13 PASS), revision 00009 deployed, then `smoke-live`
  FAIL on its second check: `GET /healthz: 404`. The 404 is Google's HTML
  page, not the app's: on the run.app hostname the edge answers `/healthz`
  itself and never forwards it. `/health` reaches the app and returns 200.
  The script now probes `/health` (this PR). Lesson for every client of the
  live service: `/health`, never `/healthz`.
